# llm-energy-benchmark

This repo stores the software for the benchmarking framework for energy consumption of Large Language Models. It`s widely based on the work of Raphael Fischer for his [AI Energy Validation Tool](https://github.com/raphischer/ai-energy-validation).
The repo is structured in the following way:
* Dataset
* Experiment Execution
* Evaluation

## Dataset
In the `dataset` folder, the tool for generation of datasets based on a input dataset (default: `Pure Dove` from Huggingface) and a Large Language Model with different language styles (simple, friendly and academic versions of the original prompt).
The tool uses a caching mechanism to ensure, that no unnecessary calls to the LLM are made.

## Experiment Execution
In the `experiments` folder, the `main.py` is used to execute an experiment on a dedicaded hardware with preset configuration parameters. The energy tracking is done by the [Lamarr Energy Tracker (LET)](https://github.com/lamarr-institute/lamarr-energy-tracker) which has to be configured and setup first according to the readme of the LET to allow the Ground Truth Energy Tracking.
The actual experiments get defined in the `run_all_ollama.sh` or `run_all_llama_cpp.sh`, which are scripts to execute multiple specified experiments in a certain order.

## Evaluation
In the `evaluation` folder, the tools for the evaluation can be found. First there is the so called `evaluation_pipeline`, which is a tool which allows the evaluation of executed experiments based on the experiment database and artifacts which are generated by executing experiments. To execute this pipeline, [Elixir's LiveBook](https://livebook.dev/) needs to be installed and executed. The tooling is similar to Python's Jupyter Notebooks but for the Elixir Progamming Language.
The evaluation pipeline structures the data, aggregates them and adds some more metrics, like the Static Energy Estimation based on the approach of the [ML Emissions Calculator](https://mlco2.github.io/impact/).
For the fitting of the Linear Mixed Models, the tooling is a little different, here the `lmm.py` can be used. The evaluation pipeline describes the usage of this file and what has to be executed first to aggregate the data accordingly.

## First Steps for setup
1. Follow the installation guide for the [LET](https://github.com/lamarr-institute/lamarr-energy-tracker)
2. Install [Ollama](https://ollama.com/)
3. Clone this repo
4. Run `pip install -r requirements.txt` to install dependencies

### Dataset Generation
Go into the `dataset` folder and run `python main.py --help` to see the available options for the dataset generation. 
Be aware, that the tool will download not only the base dataset (Pure Dove if not configured otherwise) from Huggingsface and the chosen LMM for the generation from Ollama.
The final resulting dataset will be stored in `datasets/dataset_samples`, use the `.jsonl` files for the experiments, do not rename this files, as the name stores metadata about the dataset.
#### Dataset Generation with ChatGPT and co.
If you do not want to run the LLM locally, you can use a cloud based LLM as well.
Open the `main.py` and configure the `open_ai_url` and the `open_ai_auth_token` first.
You need to pass the `mode` parameter with `open_ai` to enable this feature.
Be aware, that some parameters, like the temperature will only work in local mode.

### Executing Experiments
To execute an energy tracking experiment, you need to have a dataset first.
To see the available parameters for this tool, go to the `experiments` folder and run `python main.py --help` to get an overview.
For testing you can execute this script directly.
For real benchmarking experiments, you have to use [ML Flow](https://mlflow.org/), either manually or by using the `run_all_ollama.sh` script.
In this script you can specify the actual experiments by listing models, temperature values, the dataset and setting the seed and a timeout. 
You can finally run your configured experiments by executing `run_all_ollama.sh <YOUR EXPERIMENT TIMEOUT IN SECONDS>` in your Shell.
It's recommended to use [TMUX](https://github.com/tmux/tmux/wiki) for executing experiments, so these can run in the background.

### Evaluation
Open LiveBook and import the `evaluation_pipeline.livemd`. Follow the setup of the notebook and configure your `base_path` according to where you cloned your repo to.
You can list the experiments by connecting your experiments database by setting the path in the Database Connection section.
After this you can execute the code cells one by one for evaluation. For the artifacts evaluation it might be needed to adapt the path to your artifacts.
Some of the graphics are just for understanding, but others are exported additionally as PDF files to the `results/grafics` folder, which you have to create by hand first.
The pipeline is structured by data import of both conducted hardware types first, afterwards the data get merged and further aggregated.
The evaluation per category to investigate (influence of tracking methods, the chosen LLMs, the Language Style and the Hardware) follows section by section.
The last part with the evaluation of the artifacts is the last section, as this is the most ressource intense one.
Be aware, that depending on the number of executed experiments the execution of these cells might take a while.
